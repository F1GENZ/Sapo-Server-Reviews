# Source Extraction Map

This document maps existing Haravan app source evidence into the reusable `haravan-app-base` target. It is intentionally source-backed: source apps are references, not code to bulk-copy.

## Classification Legend

- `copy-adapt`: reuse the shape with app names removed and target contracts hardened.
- `reimplement`: keep the behavior/invariant, write new base code.
- `recipe-only`: useful later, not core V1 runtime.
- `document-only`: record as operational context or caution.
- `avoid`: do not port; target must actively prevent it.

## Non-Negotiable Extraction Rules

- Do not read/copy `.env` files, secrets, tokens, Redis/DB credentials, customer data, or merchant data.
- Do not import app-specific business logic such as orders, reviews, translation, page builder, lucky-code participants, or product-tab rendering into core.
- Haravan app lifecycle code is the only core target. Theme workflows and Shopify conventions are out of scope.
- Source code wins over source docs.

| Source app | Role in base | Use carefully |
|---|---|---|
| `F1GENZ Orders` | Best current security/auth spine: state/nonce, JWKS verification, guard, Prisma lifecycle tables, raw body handling. | Fix non-atomic state consumption, non-owner refresh lock release, `Redis KEYS` fallback, URL fragment session handoff, and uninstall race gaps. |
| `F1GENZ Review` | Best lifecycle/event breadth: webhook queue/event store, callback/frontend UX, topic aliases, uninstall cleanup, subscription handling. | Avoid random event-id fallback, URL/localStorage session token, direct no-HMAC session, and partial install-state-only persistence. |
| `F1GENZ MultiLanguage` | Best production policy patterns: Pro/trial/quota, owner-token Redis lock, uninstall tombstone, queue/worker separation, webhook retry/degraded ops. | Do not reuse `jwt.decode()` identity flow or no-HMAC direct session. Replace `getKeys` domain fallback with SCAN/indexed DB lookup. |
| `F1GENZ Multipage` | Cloudflare Pages proxy recipe inspiration. | Remove hardcoded fallback backend URL. Core must not depend on page-builder. |
| `F1GENZ Collection Tab` | Minimal token TTL and subscription snapshot intuition only. | Too small/weak for lifecycle auth. Do not use as replay defense. |
| `Lucky Code` | TypeScript frontend API-client shape and 401 redirect guard. | Avoid bearer/internal session token storage as V1 core auth. |
| `F1GENZ Feedback` | Ops/reporting inspiration only. | Not inspected in Phase 1; not a Haravan app lifecycle source. |

## Explicit Avoid List

These source patterns must not appear in the target core:

- `jwt.decode()` used as identity proof for login/install callbacks (`F1GENZ MultiLanguage` `haravan.service.ts:2805-2808`, `2909-2915`).
- OAuth state/session handoff consumed by `get` then `del`; use atomic `GETDEL` or Lua instead.
- Static/global nonce instead of per-flow nonce.
- Direct no-HMAC session issuance from public `shop + orgid` launch params.
- Session token returned in URL, hash, JSON, localStorage, or sessionStorage as a core auth path.
- Redis `KEYS`/broad `getKeys` in production path.
- Non-owner lock release (`setNx(..., '1')` then unconditional `del`).
- Random webhook fallback ID that defeats duplicate detection.
- Webhook orgid trusted from query/header without payload/domain cross-check.
- Hardcoded production backend URL in Cloudflare proxy.
- Hardcoded Redis fallback credentials or copied `.env` values.
- `pm2 --watch` or `npm install` as production deploy recipe commands.

## Target Phase 2 Inputs

Phase 2 should convert this map into contracts before code:

1. Canonical env names, including OIDC/JWKS/grant/response variables.
2. Canonical lifecycle status enum and alias normalization.
3. Prisma baseline with `Shop`, `ShopDomain`, `AppInstall`, `SubscriptionSnapshot`, and `WebhookEvent`.
4. Redis namespaces and atomic helpers.
5. API route contract for OAuth, HMAC launch, session exchange/logout, webhooks, and health.
6. One-time handoff + HttpOnly cookie session contract.
7. Webhook registration/degraded-state contract.
8. Uninstall/refresh lifecycle generation contract.

None for Phase 1. Haravan webhook registration endpoint behavior still needs real-app/manual verification in later phases, because sources disagree between connect and legacy endpoints.
